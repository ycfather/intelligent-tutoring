# 家庭试用到多用户演进：未成年人学习数据与模型服务边界

- 研究票：[家庭试用到多用户演进涉及哪些未成年人学习数据与模型服务边界？](https://github.com/ycfather/intelligent-tutoring/issues/5)；决策地图：[Intelligent Tutor：英语 ITS 基础架构与 V1 Grammar 决策地图](https://github.com/ycfather/intelligent-tutoring/issues/1)。
- 核查时点：2026-11-11，中国大陆场景；本报告只使用法律法规正式文本、主管机关文件及第一方服务条款。法规施行日与动态服务页面的访问日分开记录。
- 项目事实：先供单个家庭、单名学生在电脑浏览器联网试用，学生独立学习，家长按周了解进展；未来可能增加学生。准确年龄、实际运营主体、部署地域、模型供应商及合同均未确定。“初三”不能替代年龄确认。
- 标记约定：**事实**指来源明确支持的规定或条款；**推断**指将规则映射到候选产品的分析；**未知**指尚不能由公开资料或当前项目事实确定的问题。本报告没有确认任何真实系统已满足法律要求，也不选定供应商或最终产品政策。
- 研究材料仅含公开规则和合成数据情境，没有真实姓名、学校、学习记录或凭据。

## 可供当前决策使用的结论

1. **家庭事务例外针对具体自然人的具体处理行为。**它不能直接覆盖向家庭提供服务的应用运营者、云平台或模型服务商。应先识别每一段数据流的实际处理主体，再判断其适用条件。[个人信息保护法第72、73条][pipl]
2. **年龄与数据内容要同时判断。**不满十四周岁的个人信息整体属于敏感个人信息；十四至十七周岁仍是未成年人，不能因此视作成年人，也不能把所有学习数据自动判成普通信息。[个人信息保护法第28、31条][pipl] [未成年人保护法第2条][minors]
3. **学习闭环需要的记录，与模型调用需要的上下文，是两个范围。**表现证据、掌握度估计、家长周报、模型请求及运维日志适合分别界定目的和访问权限。下文的数据流是候选设计输入，不是已批准的数据政策。
4. **训练、留存、人工审查、删除、转交其他服务商、处理地域须分别核实。**“不用于训练”不能推出“零留存”；“国内品牌”不能推出“境内处理”；小规模也不能直接推出出境豁免。第一方条款实例见下文。[百炼隐私说明][bailian-privacy] [百炼协议6.2节][bailian-terms]

## 1. 家庭试用与对外服务：按处理行为判断

| 情境 | 已核实事实 | 对本项目的推断与未决条件 |
| --- | --- | --- |
| 家庭成员为自身家庭事务整理孩子的学习情况 | 自然人因个人或者家庭事务处理个人信息，不适用个人信息保护法第72条所指的该法；民法典仍保护自然人隐私，未成年人保护法也规定家庭保护责任。[个人信息保护法][pipl] [民法典第1032条][civil] [未成年人保护法第19条][minors] | 家庭内部使用有适用例外的可能；不能据此写成“家庭试用不受任何隐私规则约束”。家庭成员自行运行应用是否始终属于家庭事务，要结合目的、开放对象、他人参与及数据用途确认。 |
| 家庭使用外部托管应用、云数据库或模型API | 个人信息处理者的定义取决于是否自主决定处理目的、方式，不取决于客户人数。[个人信息保护法第73条][pipl] | 家庭使用者的例外不能自动传递给提供服务的主体。同一人作为家长与作为对外应用运营者的行为也要区分；外部各方是受托人、独立处理者还是共同处理者，尚需实际合同和行为证据。 |
| 向其他家庭提供试用或持续服务 | 上述家庭事务例外没有以“收费”作为判断文字。2026年施行的小型处理者规定适用于处理不满10万人个人信息的处理者，允许有条件简化，仍以遵守上位规则为基础。[个人信息保护法第72条][pipl] [小型处理者规定第2、3条][small] | 免费邀请、人数少、称为测试，均不足以单独证明仍是家庭事务；增加非家庭用户前要重新确认责任。也不应直接套用只有特定规模、业务类型才触发的大型平台义务。 |

**模型服务范围的条件性注释。**2023年生成式人工智能暂行办法第2条以向境内公众提供生成服务为适用条件，并列有未向境内公众提供服务的研发、应用情形；第22条的提供者定义包括通过API提供服务。不能仅凭“只调用别人的API”认定应用运营者不在相关责任范围，也不能仅凭“家庭使用”认定上游服务不适用。[生成式人工智能暂行办法][genai]

2026-07-15施行的拟人化互动暂行办法第2条，明确不涉及持续性情感互动的学习教育等服务不适用该办法。**这只是适用条件事实，不是本产品已获排除的结论**：当前Tutor行为尚未定稿；若未来加入持续情感陪伴、角色关系等，应重新判断。该办法的特殊数据规则不在本报告中泛化为所有教育产品义务。[拟人化互动暂行办法][anthropomorphic]

## 2. 年龄、数据分类与学生参与

| 条件 | 已核实事实 | 对候选交互的含义（推断） |
| --- | --- | --- |
| 不满十四周岁 | 个人信息适用敏感信息保护；处理须有特定目的和充分必要性、严格措施，并适用监护人同意、专门规则等要求。[个人信息保护法第28—31条][pipl] | 需要明确的监护人参与路径；不把学生自行勾选、成年账号付款或“家长已知情”直接当成充分证明。具体身份与监护关系确认方式尚待设计和专业核实。 |
| 十四至十七周岁 | 仍受未成年人保护。未成年人保护法第4、19条要求听取意见、考虑真实意愿；民事行为能力另依民法典第18—20条判断，存在十六周岁以上以劳动收入为主要生活来源等法定条件。[未成年人保护法][minors] [民法典][civil] | 十四岁不是“可独立完成所有合同或全部数据授权”的统一开关。监护人参与、学生知情和具体民事行为能力应分开确定。 |
| 年龄未知或后续跨越年龄段 | 当前只有年级信息，没有准确年龄事实。 | 不推定首名学生属于某一年龄段；可评估是否只保存年龄段或必要的阶段变化依据，避免为分龄而默认收集整份身份证。可靠性、最小化与误判处置之间仍有设计问题。 |

同意机制须结合敏感信息的单独同意和监护人同意要求核实，不能以一次无范围授权替代。个人信息保护法第13条另列法定处理依据；本票未认定日常教学服务已满足任何无需同意情形，具体适用仍须确认。[个人信息保护法第13、29、31条][pipl]

**分类事实。**主管机关2026年1月问答明确，用户标识符、教育信息、用户标签和画像等可以属于个人信息。只要能关联学生，作答、提示使用记录和推导出的掌握度估计都不能因为“是系统生成的”就排除在保护范围外；这是对定义的项目映射。十四岁以上的具体记录是否敏感，仍要看内容与泄露风险，不能一概而论。[个人信息保护政策问答（2026年1月）][pi-jan]

**学生与监护人不是可以合并的一个权限角色。**未成年人或其监护人的合法查阅、更正、删除等请求应有便捷渠道；工作人员访问未成年人信息适用最小授权及访问记录要求。[未成年人网络保护条例第34、36条][online-minors] 家长每周看进展是项目需求，并不直接回答其是否可以默认查看所有自由对话。未成年人保护法第63条对网络通讯内容的查阅有限制及列明例外；AI对话中哪些内容落入该条、监护职责如何与之衔接，需要针对交互内容确认。[未成年人保护法][minors]

**可进入规格讨论的推断：**向学生解释记录什么、谁能看；家长周报与原始对话分别设计；撤回、纠错、删除请求不只提供给付费账号持有人。以上并未决定每个角色的最终可见范围。年龄确认也不等同于一律实名采集：条例第31条针对信息发布、即时通讯等服务提出身份要求，是否覆盖某项Tutor功能，应看功能实质，不能据此要求所有练习先上传身份证。[未成年人网络保护条例][online-minors]

## 3. 将最小化落实到候选数据流

下表均为**推断／候选设计**，不是现有系统清单或法律明文指定的数据结构。依据是目的必要性、非必要信息拒绝权及网络数据处理规则；具体字段还须由学习闭环证明其必要性。[未成年人网络保护条例第32条][online-minors] [网络数据安全管理条例第21—24条][network-data]

| 数据流 | 为V1闭环可评估的最小内容 | 需要保留的边界与未知 |
| --- | --- | --- |
| 学生浏览器 → 应用 → 学习记录 | 内部学生标识、题目及版本、作答、有限提示使用、任务时间与结果，即表现证据 | 姓名、学校、班级、精确住址、通讯录与完整生日尚无本票所知的教学必要性。监护关系及账号信息与题目作答可分开授权；换成随机ID仍可能关联学生，不自动成为匿名数据。 |
| 学习记录 → 估计与调度 → 周报 | 掌握度估计及其不确定性、证据引用、学习目标、需要解释的进展 | 维持“单次表现证据”与“多次证据支持的估计”之别；不把一次错题改名为能力结论。周报只指向已确认关系的学生，向家长展示到何种粒度未定。 |
| 应用 → 模型 → 反馈 | 当前题目、教学任务、必要的局部作答／错误类型、有限上下文 | 能以公共题目或合成错误说明完成的调用，可评估不发送学生记录。确需个体化时，去掉直接标识后仍需判断是否可识别；自由文本可能主动带入家庭、健康或第三人信息，不能只靠字段名单保证最小化。 |
| 应用／模型SDK → 日志、追踪、内容审核、客服 | 先评估请求标识、耗时、错误码、模型／提示版本等技术元数据 | 记录完整请求与响应会制造额外副本。应用日志、上游安全审查、云监控、人工排障各自的内容、访问人、地点、保存与删除方式都需核实；不能只检查主数据库。 |
| 学习记录 → 导出／纠错／删除；开发与公开研究 | 按学生关联可定位的数据与衍生记录；开发复现优先合成样本 | 删除不能只删登录账号。公开仓库、工单及模型试验延续地图约定使用公开或合成材料；将真实材料去姓名后公开，不可直接宣称匿名。 |

未来图像、手写、语音等能力会增加原始文件、图像文字识别、声学特征及额外处理方；当前没有必要为未来功能预采集。届时应按实际功能重新界定数据种类、必要性和供应链，而不是把原始录音与“声纹识别”混为同一事实。[个人信息保护政策问答对生物识别及敏感信息的说明][pi-jan]

## 4. 模型服务：核实具体服务合同与功能

**已核实的责任差异。**委托处理、向另一独立处理者提供、共同决定目的和方式，具有不同约定与责任条件；不能只用“第三方”一个词覆盖。网络数据安全管理条例第12条要求向其他处理者提供或委托处理时约定相关事项并监督；相关处理情况记录至少保存3年。[个人信息保护法第20—23条][pipl] [网络数据安全管理条例][network-data]

对不满十四周岁的网络个人信息，儿童个人信息网络保护规定第16条还规定委托安全评估、协议、结束时删除及受托方不得转委托。**未知：**真实云平台、模型托管、内容审核等多层链路的角色，以及该儿童特别规则与其他委托规则如何适用于具体合同，须专业确认；不能仅因供应商提供一份通用数据处理条款就宣布已解决。[儿童个人信息网络保护规定][children]

在供应商选择前，以下是与本项目数据流直接相关的**待核实服务条件**，不是供应商打分或通用合规清单：

| 条件 | 应核实到的具体对象 | 对调用边界的影响（推断） |
| --- | --- | --- |
| 谁处理、为何处理 | 实际签约主体、自营模型／托管三方／转发API；谁自主决定安全、统计、训练等用途 | 决定委托、独立提供、共同处理分别如何判断；不能以接口兼容性代替角色判断。 |
| 训练与其他复用 | 输入、输出、用户反馈、人工标注是否用于基础模型、产品改进或其他客户；默认值、选择加入／退出及例外 | 允许完成一次推理，不当然允许后续训练。自有微调、供应商通用训练、离线教学评估也需分开界定。 |
| 留存与人工访问 | 常规请求、异常请求、缓存、文件、会话／记忆、检索库、批处理和安全审核分别保存什么、多久、何时能人工接触 | “不训练”与“零留存”分别证明；服务功能不同，结论可能不同。未披露期限就是未知，不能自行填入30天或90天。 |
| 删除与退出 | 单条删除、项目删除、注销、服务终止；备份、安全审核、已转交数据能否同步处理及何时完成 | 决定用户请求能否贯穿全链路；供应商“可删除文件”不证明安全记录或备份即时清除。 |
| 地域与转交 | API接入地、推理地、存储地、备份、支持人员远程访问、弹性调度、下游模型；不同地域版本的合同 | 品牌或接入域名不足以证明处理地点。新功能、地域或下游变化需要重新核实。 |
| 适用人群与下游服务 | 开发者账号资格、面向未成年人的下游应用是否允许、儿童数据条件、应由谁处理权利请求 | 成年人持有API账号不等于未成年人终端使用及学习数据处理条件已经满足。 |

**第一方例证，不构成推荐。**所读百炼协议标注生效日2026-09-02：6.2.5承诺仅在提供服务所需最短时间保留对话，未经授权不用于训练；6.2.4说明删除与备份可能有时间差；6.2.8、6.2.9分别涉及选定国家地区及三方模型API的不同约定。官方隐私说明同时写明不用于模型训练及会存储调用产生的数据。两类文本共同说明必须逐项核实，不能从宣传短语得出统一零留存结论；公开文本未为本项目确定可直接采用的具体留存天数、所有子处理方或未成年人场景条件。[百炼协议][bailian-terms] [百炼隐私说明][bailian-privacy]

## 5. 保存与删除：区分学习数据和证明记录

**事实。**个人信息保存以实现目的所必要的最短时间为原则，法律、行政法规另有规定的除外；儿童网络信息也不得超过实现目的所需期限。[个人信息保护法第19条][pipl] [儿童规定第12条][children] 儿童或监护人对错误和删除可提出请求；未成年人网络保护条例还规定便捷行权和拒绝时说明理由。网络数据安全管理条例要求公开期限或其确定方法及到期处置，注销等情形应删除或匿名化；法定保存或技术困难情形须限制后续处理。[儿童规定第10、19、20条][children] [未成年人网络保护条例第34条][online-minors] [网络数据安全管理条例第21、23、24条][network-data]

据此可讨论四个生命周期，**不在本报告设定具体天数**：

- **原始作答与对话：**分别证明复习、解释、纠错所需期限；完整自由对话没有因“未来可能有用”而自动获得长期保存理由。
- **衍生记录：**估计、摘要、检索索引及导出副本也可能关联学生。纠错或删除后，需决定重新计算、删除或保留哪些必要部分；这是领域与数据设计工作。
- **缓存、日志和备份：**列明实际副本与可删除能力；删除暂时不能完成时，如何停止不必要的后续使用，不能只承诺“账号注销立即全量擦除”。
- **法定证明记录：**不要把“提供／委托的处理情况记录至少3年”误读为“每份完整学习记录都至少3年”。影响评估报告与处理情况记录也有至少3年的规定，实际记录内容应与其证明目的匹配。[网络数据安全管理条例第12条][network-data] [个人信息保护法第55、56条][pipl]

**针对小规模多用户的条件性注释。**2026-09-01施行的小型处理者规定允许简便评估和审计形式，但第13条明确保留未成年人审计的法律、行政法规特别规定。未成年人网络保护条例第37条规定每年审计并及时报告；主管机关2026年4月问答进一步说明，处理未成年人个人信息，无论是否识别其身份，都应按该条开展审计。因此不能用“少于10万人”或“没有年龄字段”直接排除这一责任；特定简化或认证安排能否适用，仍需按实际条件确认。[小型处理者规定第13、14条][small] [未成年人网络保护条例][online-minors] [主管机关2026年4月问答第3问][pi-apr]

## 6. 出境：先确认路径，再判断制度条件

**路径事实。**主管机关2025年10月问答说明，境内存储数据被境外查询、调取、下载、导出的“境外”，指访问或调用行为发生地；境外机构员工在境内访问、未传至境外的情形，不因机构国别本身就构成数据出境。该口径不能简化为“外资必出境”或“服务器在国内必不出境”。[数据出境政策问答第5问][outbound-oct]

对本项目的**待核实路径**包括：浏览器直连境外接口；境内后端转交境外模型；国内平台转发至境外模型或地域；境外运维读取境内日志；备份、分析、客服或监控把可识别记录传往境外。它们是可能路径，**没有证据表明本项目已经发生这些传输**。纯公共题目与真正匿名／合成材料应另行判断，不能将仍可关联学生的随机ID记录当成匿名材料。

以下只说明对外服务可能涉及的制度，**不将家庭事务处理行为预先认定为适用，也不认定任何模型调用都须认证**：

| 条件 | 规则与限制 |
| --- | --- |
| 非关键信息基础设施运营者，当年累计出境不满10万人普通个人信息 | 2024年规定第5条的数量豁免明确不含敏感个人信息，也不含重要数据；另有履约必要等豁免情形，但不能因开发者想用某个境外模型就默认满足“确需”。[跨境流动规定][cross-border] |
| 非关键信息基础设施运营者，且不适用相应豁免；10万至不足100万人普通信息，或不足1万人敏感信息 | 依规定适用标准合同或认证路径；2026-01-01施行的认证办法第5条明确其适用条件。认证只是条件满足时的一种路径。[跨境流动规定第8条][cross-border] [出境认证办法][certification] [2026年1月出境问答第1问][outbound-jan] |
| 关键信息基础设施运营者提供相关数据；或非该类运营者达到100万人普通信息、1万人敏感信息，或提供重要数据 | 2024年规定第7条规定安全评估条件，同时保留第3—6条相应情形。本项目未被认定属于这些主体或数据类型，不能从“教育数据”直接推定重要数据。[跨境流动规定第2、7条][cross-border] |
| 免于上述机制，或已经走完某条机制 | 不能等同于全部数据保护义务消失。规则还要求依法履行告知、单独同意、影响评估等义务；适用的法定例外要按具体处理依据确认。[跨境流动规定第10条][cross-border] |

**对年龄条件的推断：**若对外服务向境外发送仍可识别的不满十四周岁学生信息，它属于敏感个人信息；不能凭“只有一名学生”直接套用普通信息的10万人以下数量豁免。是否存在其他豁免、应走何种路径以及谁承担义务，须由实际主体、数据、必要性及合同判断。小型处理者规定第10条同样不是全面豁免，也保留敏感信息以外的数量条件及其他依法行权、告知同意要求。[小型处理者规定][small]

## 7. 本票仍留下的四个决策输入

1. **家庭与服务主体：**首期由谁运行、谁可以访问、是否向家庭外开放？应按每段实际行为确认家庭事务例外，不能由“家庭试用”项目名决定。
2. **年龄与参与：**准确年龄条件怎样可靠确认且不过度采集？谁是真正监护人，学生和监护人分别能看什么、提出什么请求？完整对话的家长访问与网络通讯保护如何衔接，需专业确认。
3. **最小数据与上游合同：**哪些表现证据是闭环必要的，模型究竟需哪些局部上下文？实际供应链的角色、训练用途、人工审查、留存、转委托及地域未核实前，不能宣布可向其发送真实学习记录。
4. **保存删除与出境：**原始记录、估计、摘要、日志、备份、供应商副本如何分别到期及响应请求？跨境路径与豁免依据尚未确定，需在具体部署与服务条件形成后确认。

这些是后续规格和专业核实的输入，不是要求本票执行真实数据采集、签约、备案或部署。报告也未审查教育培训业务准入、完整内容安全制度、全部算法或平台义务，未进行技术渗透验证或实际供应商API测试。检索到的2026年9月未成年人健康安全用网规定仍以征求意见稿发布，本报告未据其提出已生效义务。[主管机关征求意见通知][draft]
